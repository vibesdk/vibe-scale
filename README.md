# Vibe-Scale

Vibe-Scale is a standard for declaring how much LLMs and coding agents were used to build and validate a project. It sets clear expectations about how much human review went into the code you're looking at.

## Scale Calculation

The 0–5 score is derived from three underlying dimensions. Authors can publish the headline score alone, or declare the precise vector for transparency.

### The V-U-T dimensions

Each dimension is scored 0, 1, or 2.

**V — Vibe coded (how much AI generated)**
- `V0` — None. No AI used.
- `V1` — AI assisted for search, autocomplete, or minor additions.
- `V2` — Significant portions (full functions or files) generated by AI.

**U — Understanding (how well the code is reviewed)**
- `U0` — Full understanding. Every line reviewed and considered.
- `U1` — Partial understanding. Spot-checked.
- `U2` — Full vibe. No human review of implementation.

*Constraint: U cannot exceed V. You cannot fail to understand code that doesn't exist.*

**T — Testing (how well behavior is validated)**
- `T0` — High coverage from automated and human testing.
- `T1` — Partial or spot testing.
- `T2` — No testing, or only AI-generated tests with no human validation.

### Algorithm

The precise score is:

```
score = (V + V×U + V×T) / 2
```

V is the root multiplier — the more AI generates, the more U and T gaps compound. A project with no AI (V=0) always scores 0, regardless of testing or review practices elsewhere.

The headline 0–5 score used above is the precise score rounded half-up to the nearest integer.
